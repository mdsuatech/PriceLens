# 7. Решения, допущения и открытые вопросы

## Решения владельца от 04.11.2026

Основной вариант PriceLens — SPA с возможностями PWA, локальной обработкой и размещением на GitHub Pages. Нативная разработка приостановлена. Создан репозиторий `yradov/PriceLens`, привязанный к рабочей папке. По дополнительному поручению владельца репозиторий сделан публичным после ответа GitHub, что текущий тариф не поддерживает Pages для приватного репозитория. Публикация сайта разрешена этим поручением. Текущий контракт находится в [документе 9](09-web-app.md).

По следующему поручению владельца репозиторий перенесён в организацию `mdsuatech` с сохранением имени, истории и публичного доступа. Новый репозиторий — `mdsuatech/PriceLens`, адрес Pages — `https://mdsuatech.github.io/PriceLens/`. Путь сборки `/PriceLens/` сохраняется. Старый адрес Pages автоматически не перенаправляется; история, настройки и офлайн-кэш браузера не переносятся на новый origin.

Рабочие допущения браузерного прототипа сохранены явно. Русский интерфейс, история из 100 событий и точность 0/2 перенесены из предыдущей реализации. Добавлены чтение отдельной фотографии как запасной сценарий и окно потери цены в 3 секунды с учётом времени браузерного OCR. Эти параметры проверяются на физических телефонах. Нативные платформенные вопросы ниже относятся к первоначальному проекту.

Первоначальный реестр версии 0.1 от 03.11.2026 сохранён ниже. Новые решения выше имеют приоритет. Остальные предложения остаются рабочими гипотезами прототипа.

## 7.1. Что следует из источника

Требования этого раздела перенесены из исходного ТЗ.

- Платформы — iOS и Android; сценарий — покупки в Румынии.
- RON → EUR и UAH; цены RON/LEI и без маркера валюты.
- Непрерывная камера и локальный OCR; автоматическая смена результата без фото каждого товара.
- Выбор текущей основной цены, учёт старой, акционной и удельной.
- Overlay с результатом, индикатор надёжности, возможность подтверждения/исправления.
- Курсы из внешнего API, ручное/автоматическое обновление, дата, кэш и работа по нему без сети.
- Настройки валют, история, фонарик, переключение камеры и ручное сканирование.
- Локальные настройки/история; собственный backend не обязателен.
- Не отправлять видеопоток; не сохранять изображения без согласия.
- Целевые задержки: первое распознавание до 1 с, обновление за 0,5–1 с в нормальных условиях.
- Корзина, другие страны/валюты, QR/штрихкоды, галерея и чеки — дальнейшее развитие; аккаунта/регистрации в MVP нет.

Flutter + ML Kit + SQLite названы в исходном обсуждении как рекомендация, а не как обязательный окончательный стек. Варианты A/Б/В размещения результата заканчиваются рекомендацией автора обсуждения, без ответа владельца продукта.

## 7.2. Реестр предложений v0.1

| ID | Предложение | Обоснование / компромисс | Где описано |
|---|---|---|---|
| D-01 | Начать с Flutter + локального ML Kit и SQLite; проверить обе платформы прототипом | Общая кодовая база; риск моста, буферов, версий и сложных ценников ещё открыт | 4.1, этап 1 |
| D-02 | Плашка рядом с ценой с переносом вниз; один вход в историю/настройки снизу; «Зафиксировать» приостанавливает OCR без фото | Компактно, нет дублирования навигации; это трактовка неокончательного UI ТЗ | 2.1, 2.5 |
| D-03 | RON фиксирован, без маркера предполагается RON с подписью; EUR+UAH включены, EUR первая; минимум одна целевая; точность 0/2, по умолчанию 2; баны и decimal, half-up | Простой интерфейс и воспроизводимые деньги; другие локали и режимы не добавляются заранее | 2.8, 3.2, 3.5 |
| D-04 | Один поставщик, оба курса одним снимком; автообновление не чаще раза в час, тайм-аут 10 с, давность 24 ч с предупреждением без блокировки | Кэш работает в магазине; датой источника нельзя подменять время запроса; политика зависит от API | 3.6, 4.6 |
| D-05 | Автоистория событий, 100 записей, без фото, снимок курса, коррекция по ID, без пересчёта прошлых записей | Нет дублей каждого кадра; одинаковые цены разных товаров иногда неразличимы | 2.7, 3.7, 4.5 |
| D-06 | OCR до 5 запусков/с, один запрос; два согласованных наблюдения; убрать карточку через 1 с потери; сомнительные форматы/условия подтверждать | Снижает дрожание, нагрузку и риск ложной уверенности; параметры требуют измерений | 3.2–3.4 |
| D-07 | Набор 60 разработческих + 60 приёмочных сцен; обычные ≥ 29/30, однозначные сложные ≥ 80%, 0 ложных уверенных на проверке; p95 ≤ 1 с | Делает качество проверяемым; цифры не взяты из исходного ТЗ и требуют принятия | 6.1–6.3 |
| D-08 | Начальная проверка Android API 24+/iOS 15.5+, задняя камера, без фонового OCR; первая компоновка портретная | Границы зависят от зафиксированных пакетов и реальных устройств; iOS требует macOS/Xcode | 4.1, 4.8 |
| D-09 | Русский UI как рабочий язык; без аналитики приложения и сохранения кадров; проверить метрики SDK и backup ОС | Язык не задан; локальная обработка не отменяет сетевые метрики зависимостей | 2.8, 4.7 |

Начальная портретная компоновка не отменяет поддержку наклона камеры к этикетке. На прототипе проверить, остаётся ли приложение в портрете или поддерживает поворот UI; финальное поведение и координаты проверить явно. Другие ориентации не обещаны до решения.

Дополнительные конкретизации этих предложений: цена за кг/л не превращается в цену товара; обычная цена приоритетнее цены по карте; неоднозначные числа не угадываются; без первого кэша EUR/UAH пусты; исторический снимок без курса не дополняется задним числом. Они описаны в документе 3.

## 7.4. Разбор пробелов и противоречий источника

| Наблюдение | Принятая рабочая трактовка |
|---|---|
| Камера непрерывная, но в навигации есть «ручное сканирование» | Автоматический поток основной, ручная фиксация дополнительная |
| История/настройки продублированы сверху и снизу | Один вход в каждую функцию, окончательный UI ещё не выбран |
| Разрешены цены без валюты, но есть ошибка «валюта не определена» | Для голого допустимого ценового числа предполагаем RON с пометкой; явную другую/неясную валюту не подменяем |
| Есть «актуальные курсы» и автономный кэш без порога | Дата данных и время получения раздельно; старый курс явно помечен |
| Требуется индикатор OCR-confidence без контракта SDK | Текстовые статусы на основе устойчивости и контекста; не выдумывать процент |
| Нужен выбор зачёркнутой/основной цены, но предлагается обычный OCR | Проверить как отдельный риск; при необходимости добавить визуальный анализ, не считать решённым одним SDK |
| Нет правила, когда писать историю | Событие распознавания, а не каждый кадр; ограничение одинаковых сумм описано |
| Нет поведения первого запуска без курса | Распознать RON, предложить обновить, не показывать фиктивную конвертацию |
| В примерах показаны суммы без единого курса/округления | Считать иллюстрациями; использовать единые тестовые коэффициенты в новых документах |
| Скриншоты упомянуты, но изображения в доступной странице не показаны | Не утверждать, что внешний вид QRbot изучен; функциональная схема подготовлена по тексту |

## 7.5. Как принимать изменения

Для решения записать дату, ответ владельца продукта и затронутые документы/тесты. Если изменилось правило цены — обновить сценарий и разметку; если курс — контракт и эталонный расчёт; если объём MVP — требования и этапы. Не менять только реестр, оставляя противоречия в остальных файлах.

После отдельного указания владельца продукта продолжать разработку выполнен первый Android-прототип; [текущее состояние](08-prototype-status.md). Рабочие допущения использованы для прототипа, а окончательные решения для MVP по-прежнему требуют уточнения из раздела 7.3. Публикация и подключение платного сервиса не выполнялись.
