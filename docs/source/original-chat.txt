Техническое задание: PriceLens

Рабочее название проекта · Mobile App · Version 1.0

Техническое задание на разработку мобильного приложения PriceLens
Техническое задание на разработку мобильного приложения PriceLens
1. Общая информация

Название: PriceLens (рабочее название).

Тип продукта: мобильное приложение для распознавания цен с помощью камеры смартфона и автоматической конвертации валют.

Основная задача: пользователь наводит камеру смартфона на ценник товара, приложение автоматически распознаёт цену в румынских леях (RON) и показывает её эквивалент в евро (EUR) и украинских гривнах (UAH).

Целевые платформы: iOS и Android.

Основной рынок: пользователи, совершающие покупки в Румынии, которым необходимо быстро понимать стоимость товаров в евро и гривнах.

2. Основной пользовательский сценарий

Пользователь открывает приложение.

Приложение запрашивает разрешение на использование камеры.

Открывается полноэкранный интерфейс камеры.

Пользователь наводит камеру на ценник товара.

Приложение автоматически распознаёт текст и числовое значение цены.

Определяет валюту RON.

Получает актуальный курс обмена.

Рассчитывает стоимость в EUR и UAH.

Показывает результат непосредственно поверх изображения с камеры.

При наведении на другой ценник результат автоматически обновляется.

Важно: сканирование должно происходить непрерывно, без необходимости фотографировать каждый товар.

3. Основной функционал
3.1. Распознавание цен (OCR)

Использовать технологию Optical Character Recognition (OCR).

Приложение должно распознавать:

Цены вида 24,99 RON.

Цены вида 24.99 RON.

Цены вида 1.299,00 RON.

Цены без обозначения валюты, например 15,99.

Цены с обозначением LEI.

Цены на небольших и крупных ценниках.

Цены при различных углах наклона камеры.

Дополнительно необходимо учитывать:

Основную цену товара.

Старую цену, перечёркнутую на ценнике.

Акционную цену.

Цену за килограмм или литр.

Несколько цен на одном ценнике.

Приоритет распознавания: текущая основная цена товара.

3.2. Конвертация валют

Основные валюты:

RON → EUR.

RON → UAH.

Формула:

EUR = RON × курс RON/EUR.

UAH = RON × курс RON/UAH.

Курсы должны загружаться автоматически из внешнего API.

Требования:

Автоматическое обновление курсов.

Возможность ручного обновления.

Отображение даты последнего обновления.

Кэширование последнего полученного курса.

Работа с последним сохранённым курсом без интернета.

Предусмотреть возможность добавления других валют в будущих версиях.

3.3. Отображение результата

После распознавания цены результат должен появляться поверх изображения камеры.

Пример:

Исходная цена: 49,99 RON

EUR: 9,83 €
UAH: 498 ₴

Интерфейс должен быть компактным, чтобы не закрывать сам ценник.

Результат должен:

Появляться автоматически.

Обновляться при наведении на другой ценник.

Исчезать, если цена больше не распознаётся.

Показывать индикатор достоверности распознавания.

Иметь возможность ручного подтверждения или исправления цены.

3.4. Настройки валют

В настройках пользователь может:

Выбрать основную валюту отображения.

Включить или отключить EUR.

Включить или отключить UAH.

Изменить порядок отображения валют.

Выбрать количество знаков после запятой.

По умолчанию показывать все три значения: RON, EUR, UAH.

4. Интерфейс приложения
Главный экран

При запуске приложения сразу открывается камера.

Верхняя панель:

Кнопка включения фонарика.

Кнопка переключения камеры.

Кнопка истории.

Кнопка настроек.

Центральная область:

Изображение с камеры.

Автоматическое распознавание цен.

Информационная карточка с результатом конвертации.

Нижняя панель:

История сканирования.

Ручное сканирование.

Настройки.

Дизайн: минималистичный, быстрый, с акцентом на камеру и крупные цифры.

В качестве UX-референса использовать предоставленные скриншоты приложения QRbot.

5. История распознавания

Приложение должно сохранять последние распознанные цены.

Для каждой записи сохранять:

Исходную цену RON.

Значение в EUR.

Значение в UAH.

Использованный курс.

Дату и время сканирования.

Пользователь может очистить историю.

Сохранение фотографий ценников не является обязательным.

6. Дополнительные функции

Предусмотреть архитектурную возможность добавления:

Распознавания штрихкодов товаров.

Сканирования QR-кодов.

Сравнения цен в разных валютах.

Расчёта общей стоимости нескольких товаров.

Поддержки других валют и стран.

7. Технические требования
Распознавание изображения

Для MVP рассмотреть:

Apple Vision / VisionKit для iOS.

Google ML Kit Text Recognition для Android.

Альтернативный вариант: Flutter с использованием ML Kit.

Распознавание должно выполняться непосредственно на устройстве, без обязательной отправки изображений на сервер.

Камера

Непрерывный видеопоток.

Автоматический анализ кадров.

Ограничение частоты OCR для экономии ресурсов.

Поддержка автофокуса.

Поддержка вспышки.

Корректная работа при слабом освещении.

Backend

Для MVP отдельный собственный backend не обязателен.

Курсы валют получать через внешний API.

Хранение настроек и истории организовать локально на устройстве.

Производительность

Целевые показатели:

Первичное распознавание: до 1 секунды в нормальных условиях.

Обновление результата: до 0,5–1 секунды после обнаружения нового ценника.

Минимальная задержка между распознаванием и отображением конвертации.

Низкое потребление батареи и ресурсов процессора.

8. Обработка ошибок

Приложение должно корректно обрабатывать следующие ситуации:

Цена не распознана.

Распознано несколько возможных цен.

Не определена валюта.

Нет интернет-соединения.

Не удалось получить курс валют.

Ценник находится вне фокуса.

Недостаточная освещённость.

Если уверенность OCR низкая, не показывать результат как достоверный. Предложить пользователю подтвердить распознанную цену.

9. Безопасность и конфиденциальность

Обработка изображений локально.

Не сохранять изображения без согласия пользователя.

Не передавать видеопоток на сервер.

Запрашивать только необходимые разрешения.

Не собирать персональные данные без необходимости.

11. Критерии приёмки

Приложение считается готовым, если:

Пользователь может открыть камеру без дополнительных действий.

Приложение распознаёт типовые ценники с ценами RON.

Правильно определяет основную цену, а не старую зачёркнутую.

Корректно рассчитывает EUR и UAH.

Обновляет результат при наведении на другой ценник.

Не требует фотографирования каждого товара.

Работает без интернета с последними сохранёнными курсами.

Не отправляет изображение с камеры на сервер.

Корректно работает на поддерживаемых устройствах iOS и Android.

Главный критерий качества продукта: пользователь должен иметь возможность быстро пройтись камерой по нескольким ценникам в магазине и практически мгновенно увидеть стоимость товаров в привычной валюте.

Как я вижу архитектуру приложения

Есть один важный технический момент: недостаточно просто распознавать все цифры на изображении. На ценнике может быть старая цена, новая цена, цена за килограмм и скидка.

Поэтому я бы разделил процесс на три этапа:

blog.livedoor

1. Камера

Получает изображение ценника в реальном времени.
softline

2. OCR + анализ цены

Находит цифры, определяет основную цену, отбрасывает старую цену и лишние значения.
dribbble

3. Конвертер

Мгновенно рассчитывает стоимость и отображает её поверх камеры.

Самое интересное: три функции, которые я бы добавил

1. Режим постоянного сканирования

Навёл на один ценник, получил результат. Перевёл камеру на следующий, получил новый. Никаких нажатий.

2. Расчёт корзины

Например, просканировал 5 товаров:

12,99 RON

24,99 RON

8,50 RON

39,99 RON

15,00 RON

Приложение автоматически считает общую сумму в RON, EUR и UAH.

3. Поддержка нескольких стран

В перспективе:

Румыния: RON → EUR / UAH.

Болгария: EUR → UAH.

Греция: EUR → UAH.

Польша: PLN → EUR / UAH.

Венгрия: HUF → EUR / UAH.

То есть получится универсальный помощник для покупок в Европе.

Моя рекомендация по разработке

Я бы не начинал с большого приложения. Сделал бы сначала работающий прототип с одной функцией: камера → распознавание ценника → две валюты.

И проверил бы его на настоящих ценниках Lidl, Kaufland и Carrefour. Именно качество распознавания будет определять, станет ли приложение действительно полезным.

И один важный вопрос по интерфейсу: как ты представляешь отображение результата?

Вариант А: небольшая плавающая карточка внизу камеры, как в моём примере.

Вариант Б: прямо рядом с ценой появляется полупрозрачная плашка с евро и гривнами.

Вариант В: рамка обводит ценник, а поверх него появляется большая карточка с конвертацией.

Я бы выбрал вариант Б. Он наиболее близок к твоей идее: навёл камеру и сразу увидел настоящую стоимость в привычной валюте.
