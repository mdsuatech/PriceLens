# 2. Экраны и пользовательские сценарии

С 04.11.2026 основной вариант — SPA/PWA. Текущий веб-интерфейс имеет три раздела с hash-навигацией. На широком экране результат расположен справа от камеры, на узком под ней. Камера запрашивается по нажатию, чтение фотографии добавлено как запасной сценарий. Первоначальные сценарии ниже используются с этими изменениями. [Текущая архитектура](09-web-app.md).

Версия 0.1 · 03.11.2026. Конкретная компоновка, тексты и тайминги ниже — **предложения v0.1**. Обязательные функции взяты из [требований](01-product-requirements.md).

## 2.1. Структура интерфейса

Три основных экрана: **Сканер → История / Настройки**. Исправление цены — модальная панель поверх сканера. Аккаунта, стартового меню и обязательного обучения нет.

Предлагаемый макет сканера:

```text
┌──────────────────────────────────┐
│ Фонарик   Сменить камеру          │
│                                  │
│           Камера                 │
│       ┌────────────────┐         │
│       │ 24,99 LEI      │         │
│       └────────────────┘         │
│        24,99 RON                 │
│        ≈ 5,00 EUR · ≈ 249,90 UAH │
│        Стабильно · Исправить      │
│                                  │
│ Курс от ДД.ММ.ГГГГ               │
│ История    Зафиксировать  Настройки│
└──────────────────────────────────┘
```

Суммы в макете рассчитаны по **условным тестовым** курсам `1 RON = 0,2 EUR = 10 UAH`; это не актуальные курсы.

В исходном ТЗ история и настройки есть и сверху, и снизу. Предлагается один набор входов снизу, чтобы не дублировать кнопки. Фонарик и смена камеры остаются сверху. Решение D-02.

Плашка с конвертацией располагается рядом с рамкой, не перекрывая цену. Если места у края нет — в свободной нижней части preview. Это обычный overlay с координатами OCR; полноценное пространственное AR не требуется. Рамка отражает выбранный кандидат, а не все найденные цифры.

## 2.2. Первый и повторный запуск

1. Если разрешение неизвестно, показать системный запрос камеры с понятной причиной: «Чтобы распознавать цены на ценниках».
2. После разрешения открыть заднюю камеру и начать OCR. Запрос курсов идёт параллельно, не задерживая preview.
3. При отказе показать «Нет доступа к камере», действие для повторного запроса, когда ОС его допускает, и переход к системным настройкам. История и настройки приложения остаются доступны.
4. Если доступ ограничен политикой устройства, объяснить ограничение без бесполезного повторного запроса.
5. При повторном запуске сразу открывается сканер с сохранёнными настройками и кэшем курсов.

Не запрашивать доступ к микрофону, галерее и местоположению. Сканирование фото/аудио не входит в MVP. При отсутствии камеры показать ошибку оборудования и сохранить доступ к истории/настройкам.

## 2.3. Состояния сканера

| Состояние | Что видно | Что происходит дальше |
|---|---|---|
| Подготовка камеры | Индикатор загрузки | Запуск preview или понятная ошибка с повтором |
| Поиск | «Наведите камеру на цену» | OCR анализирует поток |
| Проверка кандидата | Рамка, «Проверяем цену» | Ожидание устойчивого кандидата по документу 3 |
| Стабильная цена | RON, конвертация, «Стабильно», «Исправить» | Результат обновляется при смене ценника |
| Нужна проверка | Кандидаты, «Проверьте цену» | Выбрать/исправить/подтвердить; сомнение не обозначается как уверенный результат |
| Цена потеряна | Кратковременно прежняя плашка с «Ищем цену…» | Не позднее 1 с от последнего подтверждённого наблюдения плашка убирается |
| Зафиксировано | Неподвижная карточка числа, «Продолжить» | Новые результаты не заменяют карточку до продолжения |
| Ошибка камеры/OCR | Причина и действие «Повторить» | Повторная инициализация без падения |

Статус курса существует независимо от распознавания: актуальный по принятому порогу / сохранённый без сети / устаревший / отсутствует / обновляется. Ошибка курса не останавливает камеру.

Тайминг исчезновения **1 с**, стабильность из двух наблюдений и формулировки статусов — предложения, которые нужно проверить на устройстве. «Стабильно» обозначает согласованность наблюдений и правил выбора цены, а не статистическую гарантию точности OCR. Не показывать выдуманные проценты уверенности.

## 2.4. Основной поток

1. Пользователь наводит камеру на одну этикетку.
2. После выбора устойчивой основной цены появляется RON и обе включённые валюты.
3. В истории создаётся одна запись для этого события распознавания, а не для каждого видеокадра.
4. При переводе камеры на другую этикетку приложение анализирует новую цену. Если старый кандидат пропал, его конвертация перестаёт выглядеть текущей.
5. Новая стабильная цена заменяет предыдущую без нажатия кнопки.

Если видны две соседние этикетки, предпочтение получает этикетка ближе к центру кадра при достаточной определённости. Если выбрать надёжно нельзя, показать варианты или подсказку «Наведите на один ценник».

## 2.5. Подтверждение, исправление и ручное сканирование

«Зафиксировать» — дополнительная команда: приостановить OCR и удержать текущую карточку, не сохраняя фото. Если есть несколько кандидатов, открыть их выбор; если кандидатов нет, показать ввод цены RON. После подтверждения остаётся фиксированная карточка; кнопка «Продолжить» возвращает поток.

«Исправить» также приостанавливает OCR и открывает ввод исходной цены. Поле принимает неотрицательную цену с максимум двумя десятичными знаками, запятой или точкой. Группировку тысяч в ручном поле не принимать, чтобы не создавать неоднозначность. Пустое, отрицательное, буквенное значение или три десятичных знака — ошибка поля; подтверждение недоступно.

После подтверждения: пересчитать, пометить «Подтверждено вами», создать запись или обновить запись текущего события без дубликата. В истории различать источник `automatic / confirmed / corrected / manual`. Это происхождение значения, а не обещание его правильности.

Если подтверждён кандидат из живой сцены, снимок курса, использованный для карточки, закрепляется на время подтверждения. Если курса нет, сохранить RON и состояние «Без курса»; EUR/UAH остаются пустыми. Не подставлять нули. При отмене изменений вернуться к сканированию, ничего не записывая сверх уже существующей автоматической записи.

## 2.6. Курсы на экране

- При наличии курса: компактно показать дату данных. Детали источника, времени получения и обновления — в настройках.
- Без сети с кэшем: «Сохранённый курс от …». При превышении порога давности также «Курс устарел».
- Без кэша: показывать RON; вместо EUR/UAH — `—` и «Для пересчёта загрузите курс». Действие ведёт к обновлению.
- Ошибка обновления при наличии кэша: сохранить результаты по кэшу и сообщить, что обновить не удалось.
- Символ `≈` у результата показывает, что это справочный пересчёт. Фактическое списание банком может отличаться; короткое пояснение достаточно разместить в настройках курсов.

Не показывать ежедневное обязательное окно обновления. Пересчёт не требует запроса API для каждого ценника.

## 2.7. История

Список от новых записей к старым. В строке: RON, сохранённые EUR/UAH либо «Без курса», дата/время и отметка ручного вмешательства. В деталях: оба коэффициента, источник, дата курса, время получения, исходный статус. Даты хранятся в UTC, отображаются в часовом поясе устройства.

«Очистить историю» запрашивает подтверждение внутри интерфейса; подтверждение удаляет все записи истории и не трогает настройки или кэш курсов. Пустой экран объясняет, что записи появляются после распознавания. Фото, название товара, магазин и позиция на карте отсутствуют.

Предлагаемый лимит — **100 последних событий**. Правила события, повторов и исправлений определены в документе 3. Исторические суммы не меняются при обновлении курса; текущие настройки применяются только к их визуальному форматированию.

## 2.8. Настройки

| Настройка | Предлагаемое поведение |
|---|---|
| Исходная валюта | Фиксированный RON; пояснить, что цена без обозначения трактуется как RON |
| EUR и UAH | Обе включены по умолчанию; минимум одна остаётся включённой |
| Основная валюта | EUR по умолчанию; крупнее и первой среди валют результата |
| Порядок | Основная идёт первой; изменение порядка одновременно меняет основную валюту |
| Точность | 0 или 2 знака для конвертации, по умолчанию 2; исходный RON всегда с двумя |
| Курсы | Источник, дата данных, время получения, статус, «Обновить» |
| История | «Очистить историю» |

При отключении основной валюты другая включённая становится основной. Нельзя выключить обе целевые валюты. Изменения применяются сразу и переживают перезапуск. Пока предлагается русский интерфейс; язык продукта нужно уточнить (Q-04).

## 2.9. Камера и доступность

Задняя камера выбрана по умолчанию. Фонарик недоступен на камере без такой функции. При переключении сбрасываются старый кандидат и рамка; зеркало фронтального preview учитывается в координатах. При уходе в историю, настройки, фон или при блокировке телефона OCR и камера останавливаются, фонарик выключается.

После возврата на сканер запустить камеру заново и искать цену, не показывая старую как текущую. Состояния обозначать текстом и формой, а не только цветом. Проверить крупный системный шрифт, контраст на светлом/тёмном preview, системные отступы и доступность кнопок для экранного диктора.

В источнике упомянуты два скриншота QRbot, но в доступной странице они отображаются как «Выложил изображение» без самих изображений. Поэтому этот документ описывает функциональную схему, а не точное воспроизведение референса.
